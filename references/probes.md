# Наблюдения, прогоны и границы доступа

Различай четыре режима: чтение кода; наблюдения в разрешённой среде; активные изолированные
проверки; живой прогон через настоящий интерфейс (`live-drive.md`, только после согласованного
плана, обязателен при технической возможности). Не повышай автоматически evidence с code до live: по evidence.md перечисляй
конкретные источники и что каждый подтверждает.

## Авторизация

Используй уже согласованные доступы и действия текущей ревизии, не переспрашивай их.
Для недостающего доступа уточни цель и конкретные действия. Пробы на проде — только в
согласованных границах. Чтение личных переписок через Telegram требует явного разрешения
на текущую ревизию и ограничивается согласованными чатами, где владелец состоит.
Реальные сообщения, изменения внешних сервисов, платежи и воздействие на людей требуют
явного поручения; обычное «проверь бота» не разрешает отправлять сообщения живым людям.
Сообщения самому боту от аккаунта владельца на проде разрешены согласованным планом прогона:
тестовый клиент/сущности, лимит денег, уборка — в плане.

Не читать .env, ключи и файлы с секретами. Права файла сами по себе не доказывают наличие
или отсутствие секрета. Не выводи сырые логи/конфиги, если они могут содержать секреты.
Предпочитай агрегаты и обезличенные события. Не переноси продовую базу без разрешения.
SQLite на проде открывай read-only URI mode=ro; не запускай миграции/рестарт/запись.

## Изолированные проверки

Локальные диагностические проверки допустимы с синтетическими данными, временным хранилищем
и заглушёнными внешними эффектами. Сначала убедись, что конфигурация не подключается к
проду, платным API и реальным чатам. Не запускай второй polling-процесс с продовым токеном.
Если изоляцию нельзя подтвердить — оставайся на чтении и укажи недостающий доступ.

Тестовый бот/стенд с отдельными учётными данными: зафиксируй разрешённые действия, аккаунты,
чаты, лимиты расходов и очистку. Проверяй только согласованные сценарии. Внешнее действие
в тестовом чате также должно входить в авторизацию. Сбои провоцируй заглушкой, не отключением
продовых сервисов. Не меняй рабочий код мишени ради аудита без отдельного поручения.

## Что измерять при наличии данных

- Период и полнота событий; кто/какие роли пользуются, какие пути запускали.
- Попытки → успехи / частичные результаты / отмены / ошибки. При нуле попыток — N/A.
  Успех операции определяй по её результату, а не HTTP 200 или возврату модели.
- Длительность и ожидание по операциям; объём выборки. Не выводи общие проценты из единичных проб.
- Залипшие диалоги/очереди с учётом нормальной длительности именно этой операции.
- Расход движка по задаче/периоду, число вызовов и ретраев; стоимость только по известным тарифам.
- Последний успешный фоновой запуск, догон пропущенного, сверка сохранённых и доставленных объектов.

Если метрики недоступны, пиши «не измерено». Отсутствие автора в messages не является багом
само по себе. Можно использовать агрегаты jobs/events; не требуй собирать лишние персональные
данные. Если отсутствует необходимый контроль, опиши конкретные последствия этого пробела.
Не выводи плохой онбординг из использования только владельцем или малого количества попыток.

## Технические прогоны

Для существенного риска проверь обычный путь и подходящие возмущения из scenarios.md:
повтор после таймаута, две одновременные операции, рестарт, неверный ввод, частичный отказ,
устаревший объект, чужой доступ. Проверяй инварианты: данные разделены, действие не повторено,
результат сохранён, ошибка видна, повтор/отмена безопасны. Записывай ожидаемое и фактическое.
Для LLM-рискованных путей несколько повторений и вариантов входа; сохрани входы, конфигурацию
и счётчики результатов без секретов. Не объявляй выборку исчерпывающей.

## Визуальные прогоны

Следуй visual-review.md: открой фактический результат через доступный просмотрщик/клиент.
Рендер документа на синтетических данных — локальная проверка. Telegram-сообщение нельзя
считать проверенным по браузерному макету HTML. Нет доступа к клиенту — явно не проверено.
Сохраняй обезличенные снимки/артефакты в материалах отчёта. Отправка результата пользователям
не требуется для оценки: используй локальный просмотр или согласованную тестовую среду.

## Профиль aiogram / SQLite / systemd

Уточни реальные имена таблиц, полей, единиц времени, service unit и окружение по карте.
Читай состояние сервиса/счётчик перезапусков, агрегированные ошибки, события операций,
ожидающие записи, дату успешного крона. Не запускай шаблонный SELECT вслепую: даты могут быть
ISO, epoch или epoch-ms, а событие не обязательно равно пользовательской попытке.
Bot API getMe/getMyCommands/getMyDescription/getMyShortDescription — только при законно
доступном токене без его вывода. Нет доступа — оцени код/материалы и отметь ограничение.
