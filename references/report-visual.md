# Визуальная выдержка отчёта

Полный отчёт по `report-template.md` — для исполнителя и для истории. Владельцу продукта
нужен другой слой: одна страница простым языком, чтобы за минуту понять, можно ли доверять
агенту, что сломано, что делать. Выдержка обязательна для каждой ревизии и создаётся после
отчёта из его фактов; новых утверждений в ней нет.

## Носитель

- В Claude Code с доступным инструментом Artifact: собрать HTML-файл
  `docs/audits/YYYY-MM-DD-visual.html` в репозитории мишени и опубликовать его как
  Artifact (приватная страница, ссылку — в чат и в отчёт). Файл остаётся в репозитории как
  долговечная копия; Artifact — способ показать.
- В другой среде (нет Artifact, CLI без браузера, другой ассистент): тот же HTML-файл,
  самодостаточный, открывается двойным щелчком; путь — в чат и в отчёт.
- Никаких внешних ресурсов: стили и скрипты внутри файла, шрифты системные, картинки как
  data-URI или не использовать. Страница читается на телефоне и в тёмной теме.

Основа — `assets/report-visual-template.html`: заполнить плейсхолдеры `{{…}}`, лишние
секции удалить, не добавлять украшений ради украшений.

## Содержание, по порядку

1. **Вердикт светофором.** Один абзац: каким задачам агент готов, где нужен присмотр, что
   блокирует. Уровень глубины ревизии словами: «по коду», «по коду и стенду», «с живым
   прогоном». Не давать зелёный при непроверенных критичных сценариях.
2. **Что проверяли.** Плитки с числами: сценариев, находок по уровням, прогнано вживую,
   закрыто в ходе ревизии; независимая проверка была или нет. Числа только те, что есть в
   отчёте.
3. **Главное.** До пяти находок, каждая тремя строками: *что случится с человеком → почему
   → что сделать*. Серьёзность словами (критично / существенно / мешает / полировка),
   идентификаторы `AA-id` мелким шрифтом для сверки с отчётом.
4. **Карта сценариев.** Строка на сценарий, цвет по вердикту: работает / с оговорками /
   не работает / не проверено. «Не проверено» — серым, не зелёным.
5. **Что хорошо.** Проверенные сильные стороны, которые стоит сохранить при исправлении.
6. **Что не проверено и почему.** Честный список пробелов и как их закрыть.
7. **Что дальше.** Порядок исправлений (блокирующее → существенное → улучшения → полировка)
   и решения, которые нужны от владельца, каждое с вариантами.
8. **Ссылки.** Полный отчёт, журнал, карта, транскрипт прогона, план прогона.

## Язык

Простые слова, короткие предложения. Термин при первом появлении объясняется в скобках
(«отпечаток документа — контрольная сумма текста, по которой бот узнаёт ручные правки»).
Никаких путей к файлам, имён функций и JSON в основном тексте — только в ссылках и мелком
шрифте. Пользователь описывается ролью («редактор», «новичок»), не именем. Числа только
там, где они меняют решение; проценты из единичных проб не выводить. Экспертная оценка
отделена от наблюдения словами «по коду» / «в прогоне».

## Проверка перед публикацией

Каждая плитка и каждая находка сверены с отчётом; серьёзность и вердикты совпадают;
«не проверено» нигде не превратилось в «работает»; страница открывается локально без сети,
в светлой и тёмной теме, на ширине 390 px без горизонтального скролла; в ней нет секретов,
персональных данных и чужих сообщений. Ссылка на выдержку добавлена в отчёт и в чат.
