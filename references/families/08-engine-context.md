# Семейство 8 · Движок и контекст

Границы LLM и то, чем именно модель накормлена. Дыра между кодом и текстом: данные в системе есть,
но модели поданы так, что она их не находит; или модель отвечает, но бюджет, таймаут и маршрутизация
сделали ответ бесполезным.

## Что проверять

1. **Бюджет рассуждений.** Быстрая модель сжигает 32 000 токенов на размышления и возвращает
   пустоту (`finish=length`); ответ обрывается на полуслове; `max_tokens` не согласован с задачей.
2. **Таймауты по слоям.** Один таймаут на всё (7 минут зависания) против разных для быстрой
   и тяжёлой задачи; что видит человек, пока ждёт.
3. **Выбор модели.** Дешёвая модель ломается на длинном хвосте (фамилии, редкие названия);
   выбор сделан замером на реальных данных или на глаз; есть ли фиксация «почему эта модель».
4. **Молчаливый фолбэк** на другой провайдер (см. семейство 3) — здесь смотрим на качество:
   другой движок отвечает иначе, форматы расходятся.
5. **Чем накормили модель.** Справка о доске плоским списком без связи «материнская → подзадачи»;
   правка без доски в контексте — «вернул раскладку без изменений»; вопрос про детали созвона,
   а в контексте только протокол утреннего; `[:16000]` контекста; порядок и свежесть фрагментов.
6. **Маршрутизация.** LLM-роутер одним словом без контекста: ложные срабатывания («Внеси правки»
   → MEMORY); фолбэк из BOARD в MEMORY есть, обратного нет; детектор судит по первому слову
   («Стендап» → «не планирование»).
7. **Привязка к контексту.** Ответ на старое сообщение бота не привязывается к карточке; «какая
   из трёх моих карточек» модель должна угадать; короткие id из снимка вчерашнего дня.
8. **Парсинг ответа модели.** Ошибка формата = пустой ответ пользователю; JSON без валидации;
   regex-чистка вырезает лишнее (любые скобки со словом «чат»); имена при `create` отбрасываются
   молча при несовпадении.
9. **Детерминированное перед движком.** Правки по номеру, даты, имена — грамматика без LLM,
   движок только на остаток; одинаковые фразы дают одинаковый результат.
10. **Промпт против кода** (пересечение с семейством 2): промпт исключает бэклог, функция отчёта
    его считает; промпт требует «чистый текст без разметки», а рендер ждёт markdown.
11. **Наблюдаемость движка.** Журнал вызовов: задача, модель, токены, длительность, ok; при отсутствии зафиксируй ограничение. Находку наблюдаемости
    обоснуй конкретной невозможностью необходимого контроля; не требуй лишних персональных данных.

## Где искать

`llm.py` (`task_class`, `max_tokens`, `timeout`, `reasoning`), `prompts.py` (ROUTE, QA, MEMORY),
`context.py`/`board_context`, `_resolve_actions`, `json.loads(` без try, `re.sub(` над ответом,
`quickedit.py`/парсеры до движка, `log_event("llm"`.

## Прецеденты

- Планировщик v0.19.5: «быстрая модель сожгла 32 000 токенов на рассуждения и вернула пустоту»; справка
  давала карточки плоским списком, «движок задач не нашёл».
- Планировщик v0.8.0/v0.13.0: бюджет кончался «ещё в размышлениях», ответ обрывался.
- Планировщик v0.19.3: таймауты по слоям (180 с / 600 с) вместо семиминутного зависания.
- Планировщик v0.19.4: «движок принял правку, но доски у него нет — вернул раскладку без изменений».
- Планировщик v0.19.8: «детали должны быть в транскрибации того совещания» — в справке только протокол.
- Планировщик v0.15.0: детектор планирования судил по слову «Стендап».
- Планировщик v0.19.0/v0.19.9: правки узнавались по словам, владелец прислал номера; «7 -3» парсер не знал.

  выбрана замерами на реальных фото, «разница в цене — 17 центов на сотню книг».

## Типовые лечения

Бюджет и таймаут по классу задачи; журнал вызовов движка; структурированная справка со связями;
детерминированный парсер перед движком; валидация ответа с человеческой ошибкой; выбор модели
замером с записью в CLAUDE.md; маршрутизация с контекстом и обратным фолбэком.

## Дополнительные технические проверки

- Успешный JSON ещё не правильный результат: валидируй смысл, ссылки на объекты и допустимые действия.
- Данные из документов/сообщений не получают полномочия системных инструкций; инструменты
  независимо проверяют доступ, пределы аргументов и авторизацию внешних действий.
- Проследи утечку контекста между пользователями, подмену памяти, циклы вызовов и бюджеты.
- Повтори рискованные LLM-сценарии с вариантами формулировок и входов; фиксируй фактическую
  конфигурацию и размер выборки. Разовые успехи не дают общего вывода о надёжности.
