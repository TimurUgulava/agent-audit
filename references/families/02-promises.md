# Семейство 2 · Обещания против кода

Всё, что человек читает от бота или о боте, — контракт. Семейство ловит расхождение между
контрактом и поведением, включая случай «код есть, но в бою не срабатывает никогда».

## Три слоя обещаний

1. **Литералы и кнопки** — из `scripts/extract_promises.py <мишень> --md --full` (команды, подписи, тексты ответов,
   константы). Скрипт печатает «не смог разрешить: N мест» — эти места инспектор дочитывает сам.
2. **Промпты и персона** — обещания второго порядка: промпт разрешает модели сказать «сейчас
   напишу команде», «внесу правки», «отправлю протокол». На каждое обещанное действие — есть ли
   инструмент в коде и вызывается ли он из ответа модели. Плюс README, ТЗ, /help, описание бота.
3. **Реальные ответы** — если бот сохраняет свои ответы (таблица `messages` с его id), выборка
   последних 200 реплик: что люди на самом деле прочитали. Проба, `../probes.md`.

## Что проверять

1. Каждая строка слоя 1 → хендлер → действие. Особые подозреваемые: «ответьте мне здесь»,
   «нажмите, чтобы…», «я напомню», «пойдёт в вики/память/архив», «отправлю», «через минуту».
2. Кнопка меняет только статус, а текст обещает действие («В память» → `set_status` и всё).
3. **ТЗ → статус.** Таблица по пунктам ТЗ/README: сделано / частично / нет / сделано иначе.
   Для «сделано иначе» — расходится ли текст справки с новой реализацией. Идёт в приложение отчёта.
4. **Доказательство работы.** Зафиксируй попытки, успехи, частичные результаты и ошибки
   за известный период. 0 из N при N > 0 требует выяснения причин; 0 из 0 — N/A, функция
   не наблюдалась. Лог успешного вызова не доказывает качество конечного результата.
   Проверка — `../probes.md`; интерпретация — `../evidence.md`.
5. Обещания в кронах: пост обещает реакцию («ответьте здесь — перенесу»), а бот не читает
   `reply_to_message` или не хранит id поста.
6. Обещания в промптах, которые код запрещает: промпт велит исключать бэклог, а функция
   отчёта его считает (расхождение двух источников правды).
7. Мёртвый код за обещанием: функция написана и не вызывается (`append_page`, `approved`,
   который никто не читает).
8. Дрейф справки: README/help описывает поведение, которое убрали или изменили.

## Где искать

`persona.py`, `prompts.py`, `texts.py`, `README.md`, `docs/TZ-*.md`, тексты крон-постов;
`grep -n "def " | сравнить с grep вызовов` для мёртвых функций; статусы в таблицах, которые
пишутся, но не читаются (`grep -n "status" store.py` против хендлеров).

## Типовые лечения

Справка и список команд генерируются из кода; промпт получает список доступных инструментов
и запрет обещать остальное («честность про действия»); каждое обещанное действие пишет событие
в журнал, чтобы «доказательство работы» было измеримо; ТЗ-таблица обновляется при релизе.
