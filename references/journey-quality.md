# Удобство, оптимальность и качество содержания

По каждому главному сценарию оцени шесть стадий из scenarios.md. Различай дефект,
обоснованное улучшение и эстетическое предпочтение.

## Удобство

Понятен следующий шаг и цена выбора; подписи конкретны; контекст не приходится помнить;
ошибку можно исправить рядом с местом возникновения; длинная операция объясняет прогресс;
частичный успех виден; завершение даёт результат и дальнейшее действие. Проверь новичка
и возвращающегося пользователя: постоянное обучение опытного человека тоже создаёт трение.
Проверь доступность клавиатурой/скринридером, контраст и цветовые сигналы там, где применимо;
без нужных средств не утверждай соответствие стандартам доступности.

## Оптимальность

Запиши фактический путь: сообщения/действия, повторный ввод, решения, ожидания, ручные переносы,
переходы между приложениями. Время измеряй только при прогоне, остальное называй оценкой.
Предложи альтернативу на той же задаче и входных данных:
- используй уже известные сведения, но уточняй устаревшее/неоднозначное;
- объединяй связанные вопросы, давай разумные значения по умолчанию;
- допускай пакетный ввод и правку части результата;
- сохраняй прогресс и контекст при возврате;
- выдавай прямую ссылку/файл вместо инструкции найти его самостоятельно;
- убирай повторные подтверждения уже разрешённых действий, сохраняя контроль риска.

Формат: «Сейчас: шаги 1…6 → Предлагается: шаги 1…3 → Эффект → Что сохраняем → Проверка».
Меньшее число шагов само по себе не доказывает улучшение: учитывай понятность, ошибки,
обратимость, качество, время и нагрузку. Не сокращай обязательные согласования ради метрики.

## Качество содержания

Определи критерии из задачи: правильность, полнота, релевантность, отсутствие выдумок,
соответствие ограничениям, источники при необходимости, пригодность к дальнейшей работе.
Для протокола сверяй решения со стенограммой; для поиска — ответ с найденным источником;
для плана — выполнимость и покрытие требований. Формат не компенсирует неверное содержание.
Для изменчивых LLM-операций начинай с нескольких вариантов и повторений рискованного случая;
записывай набор, число попыток и результаты. Не объявляй надёжность в процентах по одному успеху.

## Находка

Покажи наблюдаемое трение, затронутого пользователя, последствия, улучшенный путь и критерий
приёмки. Для гипотезы об удобстве предложи короткую проверку с пользователем; не выдавай
собственное мнение за подтверждённое поведение всей аудитории.
