# Доказательства, вердикты и серьёзность

## Независимые поля находки

- Тип: дефект / технический риск / улучшение.
- Вердикт: подтверждено / гипотеза / отклонено. Для ячейки матрицы также:
  проверено без замечаний / не проверено / неприменимо (с причиной).
- Доказательства: code / reproduction / logs / visual / user-observation / live.
  Это набор источников, не лестница: лог не подтверждает красоту, скриншот — изоляцию данных,
  транскрипт живого прогона — вид сообщения в клиенте.
- Серьёзность S0–S3, охват, частота (измерена либо предполагается), приоритет действий.
  Серьёзность и уверенность не смешивать: потенциально критический риск бывает гипотезой.

Каждое доказательство содержит источник/место, среду, версию, условия и наблюдаемый факт.
Для воспроизведения — шаги, ожидаемое и фактическое поведение; для визуального — путь к
артефакту/снимку, клиент, viewport или размер страницы. Для кода — file:line и полный след.
Для live — путь к транскрипту, номер шага/сценария плана, среда (прод/стенд), релиз,
аккаунт-роль, ожидалось/получилось; полный текст ответа — из точки чтения, если транспорт
его не отдал. Строки кода не обязательны у визуальной или поведенческой находки, если есть
иное доказательство.
Синтетические примеры маркируй; не приписывай их реальным пользователям.

## Серьёзность

| Уровень | Последствия |
|---|---|
| S0 · критично | Чужие данные или полномочия, неконтролируемые существенные операции/расходы, необратимый тяжёлый ущерб |
| S1 · существенно | Основной сценарий не завершается, значимые потери/искажения, результат нельзя использовать, восстановление требует вмешательства |
| S2 · мешает | Сценарий завершается с лишними усилиями, задержкой, обходным путём или заметным ухудшением результата |
| S3 · полировка | Локальный недостаток без существенного влияния на задачу |

Не присваивай уровень по тематике: визуально нечитаемый основной документ может быть S1;
небольшой технический дефект — S3. Для улучшения укажи ожидаемый эффект и приоритет;
не изображай предпочтение автора критическим дефектом. Стоимость ущерба не выдумывать:
указывай механизм двойного списания даже без тарифа, сумму — лишь при известных данных.
Приоритет зависит от последствий, охвата, частоты и доступного обхода, а не от количества находок.

## Что не является доказательством

- Ноль попыток — отсутствие наблюдений, а не нулевая успешность. Успешность = успехи /
  попытки, если попытки > 0; иначе N/A. Отдельно учитывай отмену и частичный результат.
- Только владелец пользовался ботом — факт об использовании; причина требует проверки
  аудитории, стадии запуска и наблюдений. Не доказывает плохой онбординг.
- Нет нужной телеметрии — ограничение. Дефект наблюдаемости регистрируй, если показано,
  какую необходимую диагностику/контроль невозможно выполнить; не требуй хранить лишние персональные данные.
- Одно удачное выполнение — один удачный случай. Не доказывает устойчивость LLM/гонок.
- Прогон был технически возможен, но не проведён — вывод «готов к использованию» не
  обоснован; допустимо только «по коду и тестам» с названной причиной пропуска.
- Код отправил сообщение — не доказывает его вид в клиенте и удобство чтения.
- Экспертный проход — не наблюдение за реальным новичком; показатели успеха не выдумывать.

## Повторная проверка

Закрывай находку на основании критерия приёмки и подходящего доказательства. Код изменён,
но артефакт не просмотрен — визуальная находка остаётся непроверенной после исправления.
Находка из живого прогона закрывается повторным прогоном того же сценария на новом релизе,
не только тестом.
Старые уровни сохраняй в истории; при новой ревизии переоценивай по последствиям, не
конвертируй эмодзи автоматически. Дубликаты объединяй, не теряя сценариев и доказательств.
